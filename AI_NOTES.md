# AI Notes

## Tools Used
I used conversational AI tools like ChatGPT, Claude and VS code AI chat as development assistants in this assignment. I break the assignment into different phases (setup, data model, API routes, tests, documentation) and then I worked through them iteratively with the help of AI.

## 1. What was AI-generated vs. written by me

### AI-assisted

AI assisted with:

- Drafting the initial FastAPI project structure
- Generating endpoint scaffolding
- Creating Pydantic models
- Implementing the in-memory storage class
- Drafting the pytest test cases
- Improving documentation

### My contribution

I was responsible for:

- Choosing the overall architecture and project structure
- Deciding how the API should be organized
- Understanding each implementation before using it
- Running and validating every endpoint
- Verifying request validation and error handling
- Executing and reviewing the complete test suite
- Preparing the repository for submission

Instead of building the entire project in one prompt, I built it incrementally and reviewed each component before moving to the next.

---

## 2. What I validated, tested, or changed, and why

Before accepting AI-generated code, I verified that it behaved correctly

Validation included:

- Running the application locally
- Testing every endpoint through FastAPI's Swagger UI
- Running the complete pytest suite
- Testing invalid requests (missing fields, invalid dates, negative amounts)
- Confirming HTTP status codes matched REST conventions
- Verifying that a clean clone of the repository could be installed, run, and tested using only the commands documented in the README

I also reviewed the generated code to ensure it remained simple and appropriate for the assignment rather than introducing unnecessary complexity.


## 3. AI suggestions I didn't use, and why

During development several implementation alternatives were considered.

I intentionally chose **in-memory storage** instead of introducing SQLite or another database because the assignment explicitly allowed in-memory storage and no persistent database was required.

I also kept the API intentionally small and focused on the required functionality rather than adding authentication, ORM layers, or additional frameworks that were outside the assignment scope.

Finally, I used separate request (`ExpenseCreate`) and response (`Expense`) models so that expense IDs are generated by the server rather than supplied by clients. This keeps the API simpler and prevents clients from controlling identifiers.
